## 3. 项目背景（先读这些）

1. **需求原文的验收要点**：国际生工时硬校验、经费不超支、多岗工时累计、流程可追溯、数据隔离。非功能要求：响应 ≤ 2s、高峰并发、敏感信息加密、移动端适配、配置化扩展。
2. **设计文档**（规格以这些为准，代码与文档不一致也算问题）：
   - `docs/后端设计.md`：P0 架构、接口与权限表、数据隔离、规则与加锁、薪酬与预算联动
   - `docs/P1设计.md`：岗位字段配置化、模板、服务对象评价、续聘、报表导出、审计哈希链、材料上传、合规核验、财务回调
   - `docs/P2设计.md`：移动端、模拟统一认证（CAS）、学籍 / 科研 / 评教模拟对接、智能推荐、加密、登录防护、压测
   - `docs/非功能验证.md`：压测结果与配置化扩展说明
   - `server/README.md`：启动、配置、接口与权限总表
3. **技术栈**：前端 Vue 3 + Pinia + Vite（`src/`）；后端 Spring Boot 4.1.2 + MyBatis-Plus 3.5.18 + MySQL 5.7（`server/`），Java 17 语法，JWT + BCrypt。
4. **关键代码入口**：
   - 规则：`server/.../rule/RuleEngine.java`（服务端硬校验）与 `src/services/ruleEngine.js`（前端提示），两边应逐字一致
   - 数据隔离：`server/.../scope/DataScope.java`、`SqlCondition.java`、`service/SnapshotService.java`
   - 鉴权：`server/.../security/`（JWT、过滤器、`SecurityConfig`、`login/` 登录防护）
   - 业务：`server/.../service/`（录用 `ApplicationService.decide`、薪酬 `PayrollService`、财务 `FinanceService`、续聘 `RenewalService`、审计 `AuditService` / `AuditChainService`）
   - 外部系统：`server/.../integration/`、`finance/`，演示数据在 `server/src/main/resources/integration/*.json`
   - 前端接入：`src/services/api.js`（http / mock 双模式）、`src/services/http.js`、`src/stores/appStore.js`

外部系统（统一认证、学籍、科研、评教、财务）**按设计就是"接口 + 模拟实现"**，没有真实环境。不要把"没有接真实系统"报成缺陷；但模拟实现本身的安全与正确性问题要报。

## 5. 审核重点（按优先级）

### 5.1 验收要点能否被绕过（最高优先级）
请尝试构造反例，而不只是读代码：
- **国际生工时硬校验**：国际生能否通过任何路径（申请、特批、录用、续聘、工时填报、改配置）超过 `globalRules.maxWeeklyHoursIntl`？签证无效、签证有效期不覆盖聘期、学籍非"在读"时，是否所有入口都被拦住且不可特批？
- **多岗工时累计**：跨院系、跨岗位类型、待签合同、续聘合同、并发录用（两位导师同时录用同一学生）是否都能正确累计？"已占周工时 = 同一时间叠加的峰值"这一口径在后端、快照 `hoursSummary`、前端三处是否一致？
- **经费不超支**：建岗冻结、驳回释放、薪酬核算（含考核系数 1.1）、发放、财务回调、重复回调、考核改系数，能否让 `used + frozen` 超过 `total`，或让某岗位扣掉别的岗位的预留？`docs/后端设计.md` 第 7 节的不变量是否在所有路径上成立？
- **流程可追溯**：所有写操作是否都写审计日志？哈希链能否被绕过（有没有代码绕开 `AuditService` 直接插入日志）？校验能否发现改内容、删记录、改链指针？
- **数据隔离**：每个按 ID 操作的接口是否都按 `DataScope` 过滤（外院返回 404）？快照、报表导出、附件下载、推荐、评教查询、评价轮列表有没有越权读取？`SqlCondition` 拼出的 SQL 在与其他条件组合时括号是否正确？

### 5.2 安全
- 鉴权与授权：每个接口的角色限制与 `server/README.md` 权限表是否一致；有无可被学生调用的管理接口；JWT 校验、过期、篡改处理。
- 注入：MyBatis-Plus `apply`/`@Select` 中有无字符串拼接用户输入；报表导出的公式注入防护；模拟认证页 HTML 转义。
- 公开接口：`/api/public/**`（服务评价）、`/api/integration/finance/callback`（HMAC 签名、幂等、重放）、`/mock-cas/**`（票据一次性、service 白名单、开放跳转）、`/api/auth/sso/exchange`。
- 文件上传：类型判断（魔数）、大小、存储路径（路径穿越）、下载权限。
- 敏感信息：手机号 / 邮箱加密是否覆盖所有写入路径；有无明文落库、写进日志或审计、出现在快照（他人应打码）和导出里；`email_hash` 的检索是否正确。
- 登录防护：账号锁定能否被绕过（换用学号 / 邮箱 / 大小写、SSO 路径）；IP 限流取值来源（是否信任 `X-Forwarded-For`）。

### 5.3 并发与事务
- 加锁顺序（学生 → 岗位 → 申请；院系 → 经费；经费 → 薪酬；审计链头最后）是否全局一致，有无死锁可能。
- `READ_COMMITTED` 的选择是否在所有需要复核的写事务上生效；有无"先读后锁"导致用旧数据判断的地方。
- 财务模拟网关的定时回调、审计链 `beforeCommit` 写入与业务事务的交互。

### 5.4 前后端一致性与健壮性
- `RuleEngine.java` 与 `ruleEngine.js` 的校验逻辑和文案是否一致（前端只做提示，但不一致会让用户看到错误结论）。
- http 模式下所有 `api.js` 方法是否都对应到存在的后端接口，参数名一致；错误码与提示是否合理。
- 写死的日期、写死的演示数字、残留的真实高校名称（种子数据除外）。

### 5.5 可维护性（只报影响明显的）
- 重复代码、死代码、明显的性能问题（N+1 查询、全表加载后内存过滤）。
- 文档与代码不一致之处。

## 6. 已知问题（不用再报，除非你发现它比描述的更严重）

1. 管理员快照返回全部审计日志，日志量大时快照变慢、响应体变大（压测已发现，计划改分页）。
2. 登录锁定计数、评价接口限流、SSO 票据都在进程内存中，多实例部署不共享，重启清零。
3. `application.yml` 中的 JWT 密钥与加密密钥是开发默认值，生产需用环境变量 `APP_JWT_SECRET`、`APP_CRYPTO_KEY` 覆盖。
4. 外部系统均为模拟实现（见第 3 节）；`MockFinanceGateway` 无条件注册，接真实财务系统前需加条件装配。
5. 同一账号的错误密码并发到达时，锁定前可能多试几次。
6. 种子数据中经费冻结额是演示数字，岗位预留按冻结额比例反推生成（见 `scripts/gen-seed-sql.mjs`）。
7. 已有本地库在缺新表时会被自动重建为演示数据（课设演示库可接受）。
8. 部分小字号（状态胶囊 12.5px、角标 11px）在手机上低于 14px。

## 7. 报告格式

用中文，写成一个 Markdown 文件（例如 `代码审核报告.md`，放在你自己的输出目录，不要放进仓库），结构如下：

1. **结论摘要**（不超过 10 行）：五个验收要点逐条给出"成立 / 可被绕过 / 未能确认"，以及最严重的 3 个问题。
2. **问题清单**，按严重程度排序。每条包含：
   - 编号、严重程度：**阻断**（验收要点可被绕过、越权、数据损坏）/ **严重**（功能错误、安全隐患）/ **一般** / **建议**
   - 位置：`文件路径:行号`
   - 问题描述：一两句话
   - 复现步骤或反例：具体的账号、请求、数据和预期 / 实际结果
   - 依据：**已实测**（写明命令或请求与输出）/ **读代码推断**（写明推理链）
   - 修复建议：一两句话，不需要给完整代码
3. **已确认没有问题的部分**：你重点检查过且认为正确的地方，简述检查方法。这能帮助区分"没问题"和"没看"。
4. **未覆盖的范围**：时间或条件所限没有审到的部分。

要求：
- 每条问题都要能被复现或有明确推理，**不要罗列泛泛的最佳实践**。
- 同一根因只报一次，列出所有受影响位置。
- 拿不准的标为"待确认"，写明需要什么条件才能确认。
- 不要在报告中粘贴大段源码，引用行号即可。
