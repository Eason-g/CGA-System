# CGA-System 后端设计

本文是后端实现的规格。前端 `src/services/api.js` 现有的每个方法都对应一个接口，返回格式保持 `{ code, data, message }`，字段名与 mock 数据完全一致（camelCase），前端页面不需要改。

## 1. 技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| 语言 | Java 17（`maven.compiler.release=17`） | 组员装 JDK 17/21/25 都能编译 |
| 框架 | Spring Boot 4.1.2 | |
| 持久层 | MyBatis-Plus 3.5.18（`mybatis-plus-spring-boot4-starter`） | 加锁、统计等关键 SQL 手写在 Mapper 里 |
| 数据库 | MySQL 5.7 及以上 | SQL 不用 CTE、窗口函数；JSON 列可用 |
| 认证 | Spring Security + JJWT 0.13.0，密码 BCrypt | 无状态，`Authorization: Bearer <token>` |
| 测试 | JUnit 5 + Spring Boot Test + MockMvc | 连真实 MySQL 的 `cga_test` 库 |

依赖版本以上表为准；如果某个依赖与 Boot 4.1.2 不兼容，换到能用的最近版本并在 `server/README.md` 记录原因。

## 3. 统一约定

- **返回体**：`{ code, data, message }`。HTTP 状态码与 `code` 一致：200 成功，400 参数或业务规则不满足，401 未登录或 token 失效，403 无权限或合规拦截，404 不存在或不在本人数据范围内，409 并发冲突，500 内部错误。被规则拦截时 `data` 里放校验结果对象（与 mock 一致，前端会展示 `data.checks`）。
- **操作人**：一律取自 JWT。前端传来的 `operator`、`student` 参数全部忽略。
- **ID**：保持字符串主键，格式 `前缀_随机串`（如 `JOB_7F3K2A`），种子数据保留原 ID。
- **时间**：注入 `TimeService`（包装 `java.time.Clock`）。配置 `app.today` 可固定演示日期（空则用系统日期）；`app.semester-start`（默认 `2026-08-31`）用于算当前周次，`currentMonth` 由 today 得出。不得在业务代码里写死日期。
- **事务**：每个写接口一个 `@Transactional`。涉及名额、工时、预算的检查与更新必须先 `SELECT … FOR UPDATE` 锁住相关行，再检查、再写入（见第 7 节）。
- **审计**：每个写操作写一条 `audit_log`，字段与 mock 的 `addAuditLog` 一致（targetType、targetId、operatorName、operatorRole、action、opinion、beforeValue、afterValue、timestamp），另存 operatorId。
- **通知**：mock 里写 `notifications` 的地方照写（站内信）；邮件只记录 channel 文案，不真正发送。

## 4. 认证与角色

- `POST /api/auth/login` `{ account, password }`：account 可以是 username、studentNo 或 email。成功返回 `{ token, user }`；失败统一返回 401「账号或密码错误」，不区分是哪一项错。
- `GET /api/auth/me`：返回当前用户。
- token：HS256，密钥来自 `app.jwt.secret`（application.yml 给开发默认值并注释"生产必须覆盖"），有效期 8 小时。
- 种子用户的 `password_hash` 在 data.sql 里为空，启动时由初始化器把空值设成演示密码 `app.demo-password`（默认 `Cga@2026`）的 BCrypt 哈希。
- 返回给前端的 user 对象里绝不能有 `passwordHash`。

角色：`STUDENT`、`MENTOR`、`DEPT_ADMIN`、`INTL_OFFICER`、`SCHOOL_ADMIN`（校级管理员兼财务）。

## 6. 数据隔离

隔离做在 SQL 查询条件里，不是查全表后在内存里过滤。`DataScope` 根据当前用户生成条件，`SnapshotService` 和所有按 ID 取数据的写接口都用它；不在范围内的 ID 一律当作不存在（404）。

`GET /api/snapshot` 返回与 mock `db` 同结构的对象（meta、departments、users、budgets、configs、jobs、applications、contracts、timesheets、evaluations、payrolls、notifications、auditLogs），但每个集合只含本人可见的行：

| 角色 | 可见范围 |
|---|---|
| STUDENT | 已发布岗位 + 自己申请/签约过的岗位；自己的申请、合同、工时、薪酬、考核、通知；与这些记录相关的审计日志；用户表只含本人和相关岗位导师（导师只给姓名、职称、院系） |
| MENTOR | 本院系岗位 + 自己发布的岗位；自己岗位下的申请、合同、工时、薪酬、考核；这些记录涉及的学生；本院系经费 + `GA_FUND` 经费 |
| DEPT_ADMIN | `dept_id` = 本院系的全部数据，及向本院系岗位投递的学生 |
| INTL_OFFICER | 面向国际生的岗位；国际生的申请/合同/工时及全部特批单；国际生用户 |
| SCHOOL_ADMIN | 全部 |

departments、configs、meta 所有人可见；notifications 只含本人的。审计日志按其 target 是否在可见范围内过滤。

敏感字段：`passwordHash` 永不返回；手机号、邮箱只对本人和 SCHOOL_ADMIN 明文，其他人返回打码值（如 `138****2091`）。

## 7. 规则与硬校验

`rule/RuleEngine.java` 逐个移植 `src/services/ruleEngine.js` 中的函数，校验文案、返回字段与 JS 版保持一致（前端仍用 JS 版做提前提示，两边不一致会被测试发现）。要点：

- **工时上限** `getMaxWeeklyHours`：国际生读 `globalRules.maxWeeklyHoursIntl`，国内生读 `maxWeeklyHoursDefault`；学生个人 `maxWeeklyHours` 只能更严。
- **申请** `validateStudentApplication`：签证、岗位国际生开放资格是硬性条件（`overridable=false`）；语言、跨岗工时可特批。只有 `canSpecialApprove` 为真才能提交特批。申请单的 `complianceCheckResult` 记录 `currentHours/projectedHours/maxHours`。
- **录用** `validateHire`：录用时重新累计合同工时（ACTIVE + PENDING_SIGN）。超限一律拦截，除非申请已获特批且录用后工时不超过特批时记录的 `projectedHours`。同时复核状态、名额、签证、岗位开放资格。
- **工时填报** `validateTimesheetSubmission`：按周跨岗累计，超上限拦截。
- **岗位发布** `validateJobPublish`：经费可用额 = total − used − frozen；院系名额 = quotaLimit − 未驳回岗位名额之和。通过后把预计成本写入岗位的 `reservedAmount`，并加到经费 `frozenAmount`；岗位被驳回时释放。

**并发**：录用前 `SELECT … FOR UPDATE` 锁学生行和岗位行；建岗、核算、发放前锁经费行。这样两位导师同时录用同一学生，也只会有一个通过累计工时复核。

**薪酬与预算联动**（P0 新增，mock 里没有）：
- 某岗位剩余预留 = `reservedAmount` − 该岗位下所有合同已发放和待发放薪酬之和（不低于 0）。
- 核算一笔薪酬时，金额（含考核系数）必须 ≤ 剩余预留 + 经费可用额（total − used − frozen − 同经费池其他待发放薪酬超出各自岗位预留的部分）。最后一项不扣的话，多笔超预留的薪酬核算时会各自通过、合计透支。超出的不生成，在返回结果里列出被拦截的合同与原因；审计日志写明。
- 种子数据的岗位预留按各经费的演示冻结额分摊生成，保证"冻结额 = Σ max(岗位预留 − 已发放, 0)"从一开始就成立。
- 发放时：`usedAmount += amount`；`frozenAmount -= min(amount, 发放前该岗位剩余预留)`，保证不会把别的岗位的预留扣掉。发放时再校验一次 `amount ≤ total − used`。
- `submitEvaluation` 修改未发放薪酬的系数后，同样要满足上面的预算条件，不满足则保留原金额并在返回 message 里说明。

## 8. 数据库

`schema.sql` 每个集合一张表，列名用 snake_case，与前端字段一一对应。数组和嵌套对象（skills、workflowSteps、extraFields、complianceCheckResult、interviewInfo、dimensions、courseEvalSync、configs 内容）用 JSON 列；如果 MyBatis-Plus 自带的 JSON TypeHandler 与 Boot 4 的 Jackson 不兼容，自己写一个。configs 存为 `sys_config(config_key, config_value JSON)`。

初始化：配置 `app.db.init=if-empty`（默认）时，启动发现 `users` 表不存在就执行 schema.sql + data.sql；`always` 每次重建；`never` 不动。`POST /api/demo/reset` 等同于执行一次重建。

种子数据由 `scripts/gen-seed-sql.mjs` 从 `src/mock/seedData.js` 的 `createSeedData()` 生成 `data.sql`，保证与前端演示数据一致。

## 9. 测试要求

集成测试连 `cga_test` 库，每个测试类前重建数据。至少覆盖：

1. 登录成功、密码错误 401、无 token 访问 401、学生调管理接口 403。
2. 数据隔离：数学学院导师的 snapshot 里没有计算机学院的岗位；按 ID 审核外院岗位返回 404。
3. 三个已修漏洞：连续录用第三个岗位被拦截；签证无效发起特批 403；国际生上限改为 12h 后申请 14h 岗位被拦截、国内生通过。
4. 建岗超预算、超名额被拦截，经费冻结额不变。
5. 薪酬核算超预算被拦截；发放后经费 used/frozen 变化正确。
6. 并发：两个线程同时录用同一学生到两个岗位（各自不超限、合计超限），最终只有一个成功。
