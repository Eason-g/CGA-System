# 中英双语设计

国际生是本系统的核心用户（亮点 2 围绕国际生合规），界面需要随时可切换中英文，而不是只有登录页能切。

## 1. 目标与范围

- **全站可切换**：学生端顶栏、管理端顶栏（或侧栏底部）、登录页、公开评价页都放 `LanguageSwitch` 组件；切换后当前页面立即变为另一种语言，不刷新页面；选择存在 `localStorage`（`CGA_LOCALE`），刷新、重新登录后保持。
- **翻译范围**：所有界面文字（标题、按钮、表单标签、占位符、提示、空状态、表头、状态名、角色名、岗位类型、经费来源、通知 toast、路由标题、确认框）。学生端、管理端、登录页、评价页全部覆盖。
- **不翻译的内容（用户数据）**：岗位名称、岗位描述、人名、导师评语、审批意见、特批理由、工作日志、课程名、项目名、经费账户名称等由用户录入的内容，原样显示。
- **数据层的英文**：院系名称增加 `nameEn`、`shortNameEn`（种子数据给出英文名），前端用 `localized(dept, 'name')` 显示。岗位类型、角色、状态、经费来源类型按代码在前端翻译，不依赖后端文字。
- **mock 模式**：`src/services/api.js` 中 mock 后端返回的提示保持中文（mock 只用于没装后端时的离线演示）。界面文字在 mock 模式下同样双语。

## 2. 前端用法（已实现：`src/i18n/index.js`）

- 模板里：`{{ $t('nav.jobs') }}`、`:placeholder="$t('...')"`；`<script setup>` 里：`const { t, isEn, localized } = useI18n()`。
- 插值：词条写 `'已选 {n} 个'`，调用 `t('x.selected', { n: 3 })`。
- 后端双语字段：`localized(obj, 'detail')` 在英文模式下优先取 `obj.detailEn`，没有时退回 `obj.detail`；同理 `localized(res, 'message')` 取 `messageEn`。
- 词条文件：`src/i18n/locales/{zh-CN,en-US}/common.js`（通用、状态、登录、学生端、评价页）、`admin.js`（管理端）。中英两份结构必须完全一致。
- `computed` 里调用 `t()` 会随语言切换自动刷新；**不要**在模块顶层或 `setup` 里把 `t()` 的结果存成普通常量（不会更新）。
- 日期保持 `yyyy-MM-dd`；金额保持 `¥`；数字不改格式。

## 3. 后端双语（Accept-Language）

前端每个请求都带 `Accept-Language: zh-CN | en-US`（`http.js` 已实现）。后端不整体国际化，只对国际生最需要看懂的合规信息提供英文：

- `RuleEngine` 的校验项增加 `labelEn`、`detailEn`；录用复核增加 `errorsEn`；被规则拦截的响应增加 `messageEn`（例如工时超限、签证、语言、学籍、截止日、名额、预算拦截、特批不可发起）。
- `ApiResponse` 增加可选的 `messageEn` 字段（为空时不输出），**`message` 仍然是中文**，保证现有前端与测试不受影响。
- 前端 `src/services/ruleEngine.js` 的同名校验同样生成 `labelEn` / `detailEn`，英文文案与 Java 版逐字一致；状态表（`JOB_STATUS_MAP` 等）每项增加 `labelEn`。
- 站内通知、审计日志正文保持中文（属于留痕记录）。

## 4. 验收

- `node scripts/check-i18n.mjs --strict` 通过：中英词条结构一致，页面代码中没有残留中文（注释、`i18n-ignore` 标记行、`src/mock/`、mock 后端除外）。
- 在浏览器中以学生、导师、校级管理员三种身份切换到英文，逐页检查：界面文字为英文，只有用户数据保持中文；375px 宽度下英文文案不导致横向溢出；切换回中文一切如旧。
- 后端：`Accept-Language: en-US` 时被规则拦截的申请返回 `messageEn`、`checks[].detailEn`；`zh-CN` 或不带头时行为与现在完全一致。`mvn test` 全部通过。
- 前端两种模式构建成功；`node scripts/verify-p0-fixes.mjs` 通过。
