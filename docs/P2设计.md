# P2 与非功能设计

范围对应需求原文"P2：移动优化、评教联动、智能推荐"和非功能要求"响应 ≤ 2s、高峰并发支持、敏感信息加密、移动端适配、配置化扩展"，并补齐亮点 7"统一认证与学籍/科研系统对接"中目前只有文案的部分，以及登录页的真实高校名称。通用约定沿用 [后端设计.md](后端设计.md) 与 [P1设计.md](P1设计.md)。

外部系统（统一认证、学籍、科研、评教）都没有真实环境可接，一律做成**接口 + 模拟实现**：业务代码只依赖接口，模拟实现读 `server/src/main/resources/integration/*.json` 的演示数据，界面和文档都明确标注"模拟"。接真实系统时只需新增一个实现类并改配置。

## A 批：移动端适配（前端）

现状：学生端在 375px 宽时页面被撑到约 454px，卡片右侧被截断；样式里只有一个 960px 断点。

- 断点：`≤ 768px` 为手机。学生端所有页面在 375×812 下 `document.documentElement.scrollWidth ≤ innerWidth`（不允许页面级横向滚动）；表格只能在自身容器内横向滚动。
- 学生端：手机宽度下顶部导航改为底部标签栏；卡片满宽、操作按钮换行；弹窗（申请、签约、详情、对比）改为底部全屏抽屉；签名板支持触摸（pointer 事件，触摸时不滚动页面）。
- 管理端：侧栏在手机上收为抽屉（已有汉堡按钮，确认可用）；审批、工时审核、特批、合规核验这几个高频操作在手机上能完成（列表改卡片或容器内滚动，抽屉满屏）。
- 触控目标不小于 40px；字体不小于 14px；不靠悬停才能看到的信息要有替代。
- 顺带清理前端写死的日期：`JobPublishView` 默认截止日、mock 接口里的聘期起止和默认截止日，改为按 `meta.today` 推算（mock 模式下按 `TODAY_STR`）。`EvaluationView` 里写死的评教数字由 C 批替换，A 批不动。
- 验收：在浏览器里以学生、导师、校级管理员三种身份，逐页在 375×812 和 768×1024 下检查无页面级横向溢出、主要按钮可点，并截图存证。

## B 批：统一认证与系统对接（亮点 7）

### B.1 统一身份认证（模拟 CAS）
- 接口 `SsoProvider { String loginUrl(String service); SsoIdentity validate(String ticket, String service); }`，默认实现 `MockCasProvider`。
- 模拟认证中心页面 `GET /mock-cas/login?service=...`（后端直接输出一个简单的 HTML 页，标题写明"模拟统一身份认证中心（演示）"）：输入学工号和密码，校验通过后签发一次性票据 `ST-随机串`（60 秒有效、只能用一次、绑定 service），302 跳回 `service?ticket=ST-...`。
- 前端登录页增加"统一身份认证登录"按钮 → 跳到 `loginUrl`；回到前端后用 `POST /api/auth/sso/exchange {ticket, service}` 换取本系统 JWT。票据无效、过期、重复使用、service 不一致都返回 401。
- 身份映射：按学工号（username / studentNo）匹配本系统用户；匹配不到返回 403"统一认证账号未在本系统开通"。
- 配置 `app.sso.enabled`（默认 true）、`app.sso.provider=mock`。审计日志记录 SSO 登录。

### B.2 学籍系统对接
- 接口 `SisGateway`，模拟实现读 `integration/sis-students.json`：学号、学籍状态（在读/休学/毕业）、签证类型与有效期、语言证书。
- `POST /api/integration/sis/sync`（校级管理员、国际生办）：拉取并更新本系统学生的学籍状态与签证字段，返回差异清单（谁、哪个字段、旧值→新值），写审计日志。种子 JSON 里至少有一条签证有效期变更、一条状态变为休学，便于演示。
- 新增学生字段 `enrollmentStatus`；申请和录用校验增加"学籍状态为在读"（硬性条件，不可特批），前后端规则同步。

### B.3 科研系统对接
- 接口 `ResearchGateway`，模拟实现读 `integration/research-projects.json`：项目编号、名称、负责人（用户 ID）、起止日期、可用经费。
- RA 建岗时后端校验：项目编号存在、负责人是发岗导师（院系管理员和校级管理员代建时只要求同院系）、项目结束日不早于岗位预计聘期结束日。不通过返回 400 并说明原因。
- 发布页 RA 字段旁增加"校验项目"按钮，调用 `GET /api/integration/research/projects/{code}` 显示项目信息。种子 JSON 覆盖现有 RA 岗位的项目编号。

### B.4 登录页与校名
- 删除 `UNIVERSITY_LIST` 中的真实高校；校名改为配置 `app.school-name`（默认"示范高校"），由公开接口 `GET /api/public/site` 返回，前端登录页、侧栏、归档页统一读取；去掉高校切换下拉。
- 删除登录页上未实现的说法（"支持 CAS 3.0 / OAuth 2.0 / CARSI 联邦认证"等），改为如实描述"统一身份认证（演示环境为模拟 CAS）"。

## C 批：评教联动与智能推荐

### C.1 评教联动
- 接口 `TeachingEvalGateway`，模拟实现读 `integration/course-evaluations.json`：按课程号 + 学期给出评教结果（回收份数、助教相关题目均分 1–5、满意度）。
- 考核页对 TA 合同提供"同步评教结果"：`GET /api/integration/teaching-eval?contractId=` → 显示结果，导师确认后服务维度默认填"均分 × 20"，并把来源写入 `courseEvalSync`（来源、课程号、学期、份数、均分、满意度、同步时间）。
- 替换 `EvaluationView` 里写死的评教数字（目前提交固定的 48 份 / 94.2%），没有评教数据时如实显示"该课程暂无评教数据"。
- 同一合同同时有服务评价码结果和评教结果时，两者都显示，由导师选定默认值；改分仍需理由（沿用 P1 规则）。

### C.2 智能推荐
- `GET /api/recommendations`（学生本人）：对每个已发布、未申请的岗位打分 0–100，并返回理由和阻碍项：
  - 合规校验（复用 `validateStudentApplication`）：硬性条件不过的不推荐，只列为"不可申请"并给出原因；
  - 技能匹配（岗位技能与学生技能的重合度）、剩余周工时是否容纳该岗位、语言要求、同院系、截止日临近；
  - 权重写在配置 `globalRules.recommendWeights`，配置中心可调。
- 学生端岗位大厅顶部"为你推荐"展示前 3 个及推荐理由；原"技能推荐"筛选在 http 模式下改用后端排序。

## D 批：非功能

### D.1 敏感信息加密
- 用户手机号、邮箱在库中以 AES-256-GCM 加密存储（格式 `enc:v1:<base64(iv|密文|tag)>`），通过 MyBatis TypeHandler 透明加解密；密钥 `app.crypto.key`（Base64 的 32 字节，生产用环境变量，开发默认值在 application.yml 并注明）。
- 邮箱登录改为查 `email_hash`（小写邮箱的 HMAC-SHA256），不再对密文做 LIKE/等值查询。
- 已有明文数据（种子、旧库）在启动时自动加密，幂等；读取时兼容明文。
- 快照的打码逻辑不变；审计日志不记录手机号、邮箱明文。

### D.2 登录防护与安全头
- 同一账号 15 分钟内连续失败 5 次锁定 15 分钟，返回 429 并提示剩余时间；同一 IP 每分钟登录请求上限（阈值不误伤一个机房的同学）。成功登录清零。SSO 换票同样计入 IP 限流。
- Spring Security 安全头：`X-Content-Type-Options`、`X-Frame-Options: DENY`（模拟认证页除外不需要嵌入）、`Referrer-Policy`、基础 CSP。

### D.3 性能与并发
- 压测脚本 `scripts/perf-test.mjs`（Node，无额外依赖）：对运行中的后端模拟 N 个并发用户，场景为登录、各角色拉取快照、岗位申请、导师录用、薪酬核算；输出每个接口的请求数、错误数、平均、p95、最大耗时。
- 目标：50 并发下所有接口 p95 ≤ 2s；200 并发登录 + 快照无错误。结果和机器配置写进 `docs/非功能验证.md`，达不到时先做优化（索引、连接池、快照查询合并）再测，并如实记录。
- 配置连接池（HikariCP）大小与超时；确认并发录用测试在压测下仍不突破工时上限。

### D.4 配置化扩展（文档）
- 在 `docs/非功能验证.md` 汇总已有的配置化能力（审批流、岗位字段、考核模板、工时规则、推荐权重、外部系统实现切换）以及新增一种外部系统实现的步骤。
