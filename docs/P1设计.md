# P1 设计

P1 在 P0 的基础上补齐：考核、报表、合规强化、财务对接，以及接手时列出的缺口（岗位模板、差异化字段写死、材料上传、服务对象评价、报表导出、审计防篡改）。通用约定（返回体、操作人取自令牌、DataScope、加锁、审计、TimeService、不写死日期、无真实高校名称）沿用 [后端设计.md](后端设计.md)，本文只写新增部分。

前端两种模式：新功能只要求 http 模式可用；mock 模式下对应按钮可以提示"该功能需要连接后端"，不必在 mock 里实现。

## 第一批：配置化与考核

### 1.1 岗位类型差异化字段（亮点 1、6）

现在 TA/RA/GA 的专属字段写死在 `JobPublishView.vue`。改为配置驱动：

- `sys_config` 新增 `jobTypeSchemas`，按岗位类型给出：
  - `fields`：字段定义数组 `{ key, label, type, required, placeholder, options }`，`type` 取 `text` / `textarea` / `number` / `select` / `lines`（多行文本，存为字符串数组）/ `date`。
  - `allowedFundSources`：该类型允许使用的经费来源，默认 TA→`TA_FUND`，RA→`RA_PROJECT`，GA→`GA_FUND`。
  - `defaults`：时薪、周工时、周数的默认值。
- 种子配置复现现在页面上的全部字段，页面效果不变。
- 发布页按配置渲染字段；校级管理员可在配置中心增删改字段（改 label、必填、选项，新增自定义字段）。
- 后端建岗时按配置校验：必填字段不能为空、`select` 值必须在选项内、经费来源必须在 `allowedFundSources` 内（"经费来源按岗位类型差异化"的硬校验）。未知字段原样保存。
- 两个派生字段由后端统一生成，前端不再自己拼：TA 的 `languageRequirement`（由 `minLangScore` 得出）；RA 的 `milestones`（由 `milestonesText` 每行一条生成，`dueDate` 按聘期均分，不写死）。

### 1.2 岗位模板

- 新表 `job_templates`：`id, name, type, dept_id（空=全校通用）, payload JSON（除标题外的岗位表单字段）, created_by, created_at`。
- 接口：`GET /api/job-templates`（本人可见：全校通用 + 本院系），`POST /api/job-templates`（导师、院系管理员存本院系；校级管理员可存全校通用），`DELETE /api/job-templates/{id}`（创建者或校级管理员）。
- 发布页增加"从模板创建"和"存为模板"。种子数据给每种类型各一个全校通用模板。
- 模板数据也放进快照（`jobTemplates`），前端仍可从 `store.db` 读。

### 1.3 服务对象评价

TA 服务的是课程学生，GA 服务的是来办事的师生，他们大多不是系统用户，所以用"评价码"：

- 导师在考核页为某份生效合同开启一轮服务评价，生成 8 位评价码（大写字母和数字，去掉易混字符）和截止日期；可关闭。新表 `feedback_rounds(id, contract_id, code, opened_by, deadline, status)`。
- 公开页面 `#/feedback`（无需登录）：输入评价码 → 显示岗位名称和助理姓名（只显示姓氏加"同学"）→ 打 1–5 星、可写一句话 → 提交。新表 `service_feedback(id, round_id, rating, comment, client_hash, created_at)`。
- 公开接口 `GET /api/public/feedback/{code}`、`POST /api/public/feedback/{code}`：按 IP 和评价码限流；同一浏览器每轮只能提交一次（前端生成随机 ID 存 localStorage，后端只存它的 SHA-256）；截止后或关闭后拒绝。
- 助理本人在系统里看不到单条评价，只看到平均分和条数。
- 提交周期考核时，`service` 维度在该合同有评价时默认填入"平均星级 × 20"，导师可以改，但修改要写理由，理由进审计日志。

### 1.4 续聘

- `POST /api/contracts/{id}/renew`：岗位导师本人、校级管理员。条件：合同为 ACTIVE、最近一次考核 `renewalEligible=true`、岗位仍为 PUBLISHED，并通过录用时同样的跨岗工时复核和国际生签证复核（签证有效期必须覆盖新聘期）。
- 通过后生成新的待签合同，开始日为原合同结束日次日，周数同岗位；原合同不变。考核不合格时返回 403 并写明原因。
- 考核页对符合条件的合同显示"发起续聘"。

## 第二批：报表与审计

### 2.1 报表导出

- `GET /api/reports/{type}/export?format=xlsx|csv&month=&deptId=`，数据范围按 DataScope。`type`：
  - `jobs`：岗位统计（类型、院系、名额、已聘、预计成本、状态）
  - `hires`：聘用名单（学生、学号、岗位、聘期、周工时、国际生、合同状态）
  - `timesheets`：工时汇总（学生 × 月份，已审核/待审核/驳回工时）
  - `payrolls`：薪酬发放（月份、学生、岗位、经费来源、金额、状态、凭证号）
  - `budgets`：经费执行（总额、已发、冻结、可用、执行率）
- xlsx 用 Apache POI，表头加粗、冻结首行、列宽自适应；csv 用 UTF-8 带 BOM，Excel 打开不乱码。
- 防公式注入：以 `= + - @` 或制表符、回车开头的文本单元格前加单引号。
- 文件名形如 `聘用名单_2026-11.xlsx`，用 `Content-Disposition` 的 `filename*` 编码中文。导出写一条审计日志。
- 报表页每张表加"导出 Excel / 导出 CSV"按钮；前端用带令牌的 fetch 下载（不能用裸链接，因为要带 Authorization）。

### 2.2 审计日志防篡改

- `audit_log` 新增 `seq`（自增序号）、`prev_hash`、`hash`。`hash = SHA-256(prev_hash + "|" + seq + "|" + targetType + "|" + targetId + "|" + operatorId + "|" + operatorName + "|" + operatorRole + "|" + action + "|" + opinion + "|" + beforeValue + "|" + afterValue + "|" + timestamp)`，首条的 prev_hash 为 64 个 0。
- 追加日志时先锁链头（单行表 `audit_chain_head` 的 `FOR UPDATE`），保证并发写入时链不分叉。种子日志在初始化时按顺序补算哈希。
- `GET /api/audit/verify`（校级管理员）：从头重算，返回 `{ ok, checked, brokenAt }`，`brokenAt` 为第一条不符的日志 ID 和原因（内容被改 / 链断开 / 被删除导致序号不连续）。
- 审计页加"校验完整性"按钮，显示结果。测试里直接用 SQL 改一条日志的 opinion、删一条，校验都要能报出来。
- 说明：这能发现篡改，但不能阻止拥有数据库权限的人篡改；答辩时如实这样讲。

## 第三批：材料、合规与财务

### 3.1 材料上传

- `POST /api/attachments`（multipart）：字段 `file`、`kind`（`RESUME` 简历 / `LANG_CERT` 语言证明 / `VISA` 签证或居留许可 / `OTHER`）。只收 pdf/jpg/png，单个 ≤ 10MB，按文件头判断真实类型，不信任扩展名。文件存 `app.upload-dir`（默认 `server/uploads/`，加入 .gitignore），文件名用随机 ID，库里存原名、大小、SHA-256、类型、上传人。
- `GET /api/attachments/{id}`：上传人本人、其申请所投岗位的导师、本院系管理员、国际生办（仅国际生的材料）、校级管理员可下载，其余 404。
- 申请时可附简历和其他材料（`attachmentIds`），申请单保存附件 ID 列表。个人主页可上传语言证明和签证材料。
- 导师筛选抽屉显示附件并可下载。

### 3.2 合规强化（亮点 2）

- **语言证明核验**：学生上传语言证明后状态为"待核验"；国际生办在新的"合规核验"列表里查看材料，核验通过才把 `languageValid` 置真（并可修正 `languageLevel`）。新接口 `POST /api/users/{id}/compliance-verify`（国际生办、校级管理员），写审计日志。未核验的语言证明在申请校验里视为未通过（可特批）。
- **签证有效期覆盖聘期**：录用和续聘时，国际生签证有效期早于合同结束日则拦截，不可特批，文案写明到期日和聘期结束日。申请阶段给出提示性检查项（不拦截）。
- **签证到期预警**：异常扫描增加"签证 30 天内到期"（前端 `scanAnomalies` 与后端规则同步）。
- 国际生签约时的《工时合规声明》保持现状。

### 3.3 财务对接与状态回写

- 新增接口 `FinanceGateway`，默认实现 `MockFinanceGateway` 模拟学校财务系统：发放改为两步。
  1. 校级管理员"提交财务"：薪酬状态 `PENDING_PAY → SUBMITTED`，经费此时不变，生成财务流水号。
  2. 财务系统回调 `POST /api/integration/finance/callback`（公开接口，用 HMAC-SHA256 签名校验，密钥 `app.finance.callback-secret`）：成功则 `SUBMITTED → PAID`，写凭证号，并按 P0 规则扣减经费；失败则 `SUBMITTED → PAY_FAILED` 并写原因，经费不变，可重新提交。回调要幂等（同一流水号重复回调不重复扣款）。
- 演示用：`MockFinanceGateway` 在提交后由定时任务（几秒后）自动发起回调，成功率可配置（默认 100%）；另提供校级管理员可用的"模拟财务回调"按钮，可选成功或失败，便于答辩现场演示失败重试。
- 薪酬页状态显示增加"已提交财务"和"发放失败"，失败行可"重新提交"。
- 原来一步到位的 `POST /api/payrolls/{id}/payout` 保留给 mock 模式兼容，http 模式前端改用两步流程。
